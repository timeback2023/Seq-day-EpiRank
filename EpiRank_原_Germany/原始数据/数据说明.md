## 1. 公共前置：400 县规范行序

6 份表格共用**同一套行序**，`db_ID = 0..399`。该行序可从原始数据完全推导：

```python
# build_tables.py :: load_canon()
m = pd.read_csv('原始数据/OD/Merging_List_Districts.csv', sep='\t')   # 401 行
m = m[m['AGS num'] != 16056].sort_values('AGS num').reset_index(drop=True)   # → 400 行
```

要点：

- **`Merging_List_Districts.csv` 有 401 行**，比 400 县方案多一行 **AGS 16056 = Eisenach**。
  2019 年行政区划调整中 Eisenach 并入 Wartburgkreis(16061)，400 县方案不再单列，
  因此这行在所有表中都被剔除（`Flu.xlsx` 是"第 401 行被丢弃"，其余表则因原始数据本身无此 AGS 而天然不存在）。
- **必须按 `AGS num` 升序排序**，不能沿用 `Merging_List_Districts.csv` 的原始行序——
  该文件中 `Göttingen (3159)` 出现在 `Goslar (3153)`、`Helmstedt (3154)` 之前，存在一处乱序。
  按 AGS 排序后与 `bs.xlsx` 的行序完全吻合（400/400 命中）。
- 原始 RKI 文件（`ev` / `nv` / COVID）里的 AGS 是**带前导零的 5 位字符串**（如 `01001`），
  而 `Merging_List_Districts.csv` / `population.csv` / `cn.xlsx` 里是**去零整数**（如 `1001`）。
  所有映射都通过 `int()` 归一化后进行。
- **柏林(11000)在原始数据里是拆开的**：`ev` / `nv` / COVID 三个 RKI 文件都把柏林拆成
  12 个"县"（11001–11012），`population.csv` 和 OD 矩阵则只有 11000。
  映射时统一按 `11001 ≤ AGS ≤ 11012 → 11000` 归并。

## 2. `Flu.xlsx` —— 流感（sheet `2015_2020`）

**原始文件**：`原始数据/flu/cases.csv` — 401 行 × 1036 列，列名 `x1 … x1036`（**无日期表头**），
每格是某县某 ISO 周的流感报告病例数。

**提取规则**（`build_tables.py :: build_flu()`）：

```python
c = pd.read_csv('原始数据/flu/cases.csv')          # (401, 1036)
cases = c.iloc[:400, -312:].sum(axis=1)            # 前 400 行 × 末尾 312 周
```

| 环节 | 处理 |
|---|---|
| 行筛选 | 取**前 400 行**（行序 = 规范行序）；第 401 行是被剔除的 Eisenach，合计 2,945 例 |
| 列筛选 | 取**末尾 312 个周列**，即 `x725 … x1036`（1036 − 312 = 724，前 724 列全部丢弃） |
| 聚合 | 沿周列求和，不做任何缩放/平滑 |

**第 401 行是 Eisenach 的判定依据**（`cases.csv` 不含 AGS 列，故用排除法证明）：
前 400 行的年均发病率落在 13–1,187 /10 万区间；第 401 行的 2,945 例若要不超出该上界，
其所属县 2018 年人口需 ≥ 41,367。`Merging_List_Districts.csv` 中人口满足此条件的县有 396 个，
**剔除已在 400 县内的 395 个后，唯一剩下的就是 AGS 16056 = Eisenach（42,370 人，折算 1,158 /10 万）**。

**结果**：400 县合计 **1,024,212** 例（+ 被丢弃的 Eisenach 2,945 = 全表末 312 列总和 1,027,157）。
最大 Berlin 35,664（次位 München 34,035、Hamburg 27,918），
最小 Kempten (Allgäu) 84（次位 Olpe, Kreis 105、Delmenhorst 159）。

**时间口径**：`cases.csv` 的周列没有日期表头，确切起止日期无法从文件本身确定。
按 `population.csv` 覆盖 2000–2019（20 年 ≈ 1,040 周，与 1,036 周吻合）反推，
若 `x1 = 2000-01-03`（ISO 2000-W01 周一），则 `x725…x1036` ≈ **2013-11-18 … 2019-11-04**
（ISO 2013-W47 … 2019-W45）——**此为合理推断，非文件事实**。
sheet 名 `2015_2020` 是宽泛标注。EpiRank 实际只把它当作一个"6 年累计"的横截面权重使用。

**校验**：`build_tables.py --check` 报 L1 = 0；openpyxl 逐单元格（含空白格位置）比对 401×3 全部相等，差异 0。

## 3. `ev.xlsx` —— 肠病毒（sheet `2010_2015`）

**原始文件**：`原始数据/germany_enterovirus_county_weekly.csv` — 236,488 行 × 7 列
（`geo_name, geo_code, date, count, disease_name, disease_code, year`），
= **412 个地区 × 574 个周一日期**（2005-01-03 … 2015-12-28），`count` 为该周该县病例数。

**提取规则**（`build_tables.py :: build_ev()`）：

```python
ev['ags'] = ev['geo_code'].str.extract(r'\[([\d?]{5})\]\s*$')   # 取 geo_code 末尾的 5 位 AGS
ev = ev[ev['ags'] != '?????']                                  # 丢弃 Unbekannt（574 行，count 全为 0）
ev['ags'] = ev['ags'].astype(int);  ev.loc[ev.ags.between(11001,11012), 'ags'] = 11000
cases = ev.groupby('ags')['count'].sum()                       # 全时段按县求和
```

| 环节 | 处理 |
|---|---|
| AGS 解析 | 正则从 `geo_code`（形如 `…&[07131]`）尾部取 5 位 AGS，**保留字符串**以区分 `?????` |
| 未知地区 | `?????` = `Unbekannt` 共 574 行，`count` 合计为 0，丢弃无影响 |
| 柏林 | 11001–11012 → 11000（`Unbekannt` 与 12 区共 412 个地区 = 400 县 − 1(无16056) + 12 区 + 1 未知） |
| 时间 | **全时段求和，不做年份筛选**。574 周中 2005–2014 的 `count` 全为 0 |
| 缺失县 | 原始数据不含 16056(Eisenach)，400 县天然齐全，无需补零 |

**结果**：400 县合计 **172** 例，**仅萨克森州 11 个县非零**：

| 县 | 例数 | | 县 | 例数 |
|---|---:|---|---|---:|
| Leipzig, Stadt (14713) | 67 | | Bautzen, Landkreis (14625) | 6 |
| Dresden, Stadt (14612) | 38 | | Erzgebirgskreis (14521) | 3 |
| Görlitz, Landkreis (14626) | 22 | | Sächsische Schweiz-Osterzgebirge, Landkreis (14628) | 2 |
| Leipzig, Landkreis (14729) | 11 | | Vogtlandkreis (14523) | 2 |
| Nordsachsen, Landkreis (14730) | 10 | | Zwickau, Landkreis (14524) | 2 |
| Meißen, Landkreis (14627) | 9 | | | |

**时间口径**：全部 172 例都落在 2015 年，共 **74 条"县-周"阳性记录**，
日期为 2015-03-16 单周 + 2015-08-31 至 2015-12-21 连续 17 周。
sheet 名 `2010_2015` 是宽泛标注，实际有效信息只有 2015 年下半年。

**校验**：400/400 县逐一精确相等，L1 = 0。

## 4. `nv.xlsx` —— 诺如病毒（sheet `2015_2020`）

**原始文件**：
- `原始数据/norovirus_germany_county_2015_2020_raw.csv` — 2,472 行 × 7 列
  （`incidence, geo_name, geo_code, year, start_week, disease_name, disease_code`）
  = **412 个地区 × 6 个年份（2015–2020）**，`start_week` 恒为 1。
  **关键：`incidence` 是年发病率（例/10 万人），不是病例数**，必须先乘人口还原。
- `原始数据/flu/population.csv` — 401 行 × 20 列（AGS + 2000…2019 人口），提供折算所需人口。

**提取规则**（`build_tables.py :: build_nv()`）：

```python
nv = nv[nv.ags != '?????']                       # ① 丢弃 Unbekannt（6 行，incidence 全为 NaN）
berlin = nv[nv.ags ∈ 11001..11012].groupby('year')['incidence'].mean()   # ② 柏林：12 区同年份发病率取简单平均
nv = concat(nv[非柏林], berlin.assign(ags=11000))
nv['population'] = pop[ags, year == 2020 ? 2019 : year]                # ③ 人口：2020 无列，沿用 2019
nv['cases'] = nv.incidence * nv.population / 100000                     # ④ 发病率 → 病例数
cases = nv.groupby('ags')['cases'].sum().fillna(0)                     # ⑤ 6 年求和
cases = np.rint(cases).astype(int)                                     # ⑥ 四舍五入到整数
```

| 环节 | 处理 |
|---|---|
| 未知地区 | `?????` = `Unbekannt`，6 个年份 `incidence` 全为 NaN，丢弃 |
| **柏林** | `population.csv` 只有 11000 总人口、无分区人口，故先对**同一年 12 个区的发病率取简单平均**，再乘柏林总人口（等人口假设） |
| 人口年份 | 2015–2019 取当年列；**2020 在 `population.csv` 中无对应列，统一回退到 2019 列** |
| 缺失县-年 | `incidence` 为 NaN 的 5 个县-年按 0 计：`SK Hof`(09464) 缺 2016；`SK Kempten`(09763) 缺 2016/2017/2019/2020 |
| 取整 | `np.rint`（banker's rounding）在县一级取整，而非逐年取整 |

柏林逐年平均发病率与还原病例数：

| 年份 | 2015 | 2016 | 2017 | 2018 | 2019 | 2020 |
|---|---:|---:|---:|---:|---:|---:|
| 平均发病率 (/10万) | 92.80 | 122.82 | 167.63 | 174.54 | 188.26 | 58.10 |
| 柏林人口 | 3,520,031 | 3,574,830 | 3,613,495 | 3,644,826 | 3,669,491 | 3,669,491(←2019) |
| 还原病例数 | 3,267 | 4,391 | 6,057 | 6,362 | 6,908 | 2,132 |

**结果**：400 县合计 **635,413** 例。最大 Berlin 29,116，最小 Kempten (Allgäu) 21（缺 4 年所致），
均值约 1,589/县。2020 年均发病率仅约 58/10 万（往年 93–188），与新冠防控措施效应相符。

**校验**：400/400 县 `np.rint` 后逐一精确相等，L1 = 0（重建浮点和 635,409.11，取整后 635,413）。

## 5. `cn.xlsx` —— 通勤 OD 矩阵（sheet `353C`，无疾病信息）

**原始文件**：`原始数据/OD/trip_count_matrix_..._2024.csv` — 3,276,177 行 × 5 列
（`start_county, end_county, age_group, activity_dest, trip_cnt`），**2024 年出行矩阵**。
`metadata.csv` 说明取值：`age_group` 1–5（0-19/20-49/50-64/65-79/80+ 岁）、
`activity_dest` 1–7（工作/教育/购物/休闲/私事/其他/回家）。

**提取规则**（`build_tables.py :: build_cn()`）：**对 4 个维度全部求和**，只保留 OD 对。

```python
np.add.at(M, (start_county → 行号, end_county → 行号), trip_cnt)   # 400 × 400
```

原始 CSV 本身已是 400 县 AGS 空间（柏林为 11000，无 16056），无需归并。

**结果**：400×400 矩阵，**非零边 14,311 条**，总量 **255,993,172** 人次
（其中对角线"本地通勤"196,771,248 人次，占 76.9%）。非零边数 = 重建后矩阵中 `(OD > 0)` 的单元格数。

**写盘版式**（GUI 的 `build_commuting_network` 依赖此布局，`EpiRank_GUI.py:282`）：

| 区域 | 内容 |
|---|---|
| 第 1–3 行 | AGS 表头（F1:OO405 重复 3 次），A–E 列留空 |
| 第 4–5 行 | 完全空行 |
| 第 6–405 行 | 400 个县：A 列 `seq_no`(0–399)、B 列 AGS、C 列 AGS、D/E 列留空、F…OO 列 = OD 矩阵 |
| 值为 0 | **留空**（不写 0），共 145,689 个空单元格 |

写盘时必须用 `to_excel(..., index=False, header=False)`，否则 pandas 会多写一行列名。

**校验**：400×400 矩阵 L1 = 0，逐格一致；A 列 `seq_no`、版式行列块位置均一致。

## 6. `COVID-19.xlsx` —— 新冠（sheet `2003`，**不是年份**）

**原始来源**：`原始数据/SARS-CoV-2-Infektionen_in_Deutschland-main/`
（RKI 官方开放数据集，版本 DOI `10.5281/zenodo.22719679`，概念 DOI `10.5281/zenodo.4681153`）。

**为什么无法本地复现**：核心数据文件 `Aktuell_Deutschland_SarsCov2_Infektionen.csv`
在本地**只有 134 字节**，是 Git-LFS 指针：

```
version https://git-lfs.github.com/spec/v1
oid sha256:ec6c87c4d8f606439a35d8c2982c7439ba52c0e4a226a588d0e2e90ffd88e909
size 413314969
```

`.git/lfs/objects/` 中也没有对应缓存对象，故 413 MB 的真实 CSV 未落地，无法逐行复算。
如需复现，先取回真实文件：

```bash
git lfs install
git lfs pull --include="EpiRank_原_Germany/原始数据/SARS-CoV-2-Infektionen_in_Deutschland-main/Aktuell_Deutschland_SarsCov2_Infektionen.csv"
```

**取回后的提取规则**（`build_tables.py :: build_covid()` 已实现，取回 LFS 文件即可自动启用）：

1. RKI 的 `Aktuell_*` 是**每日全量快照**（快照日 00:00 前上报的全部感染，
   每日完全重新生成并覆盖前日数据），字段定义见 `Readme.md:77-79, 143-152`
   与 `Metadaten/schemas/tableschema_Aktuell_Deutschland_SarsCov2_Infektionen.json`。
2. **过滤 `NeuerFall ∈ {0, 1}`，排除 `-1`**（`-1` 表示该病例组被撤銷冲销，`AnzahlFall` 为负）。
3. 按 `IdLandkreis` 汇总 `AnzahlFall`。`IdLandkreis` 是 5 位整数，
   **11001–11012（柏林 12 区）先合并为 11000**。
4. 丢弃 `16056`(Eisenach) 与 `?????` 等未知行，映射到 400 县规范行序。
5. 输出 `(county, town, cases)`，`county`/`town` 取自 `bs.xlsx`。

**快照版本**：`Metadaten/zenodo.json` 与 `citation.cff` 载明 `publication_date` / `version` =
**2026-09-12**，`COVID-19.xlsx` 文件时间戳为 **2026-09-13 22:27**，即快照次日生成。

**结果**：400 县合计 **39,201,579** 例。最大 Berlin 1,477,017，无零值县，最小 13,209。
`county`/`town` 与 `bs.xlsx` 逐行完全一致。

**外部参照**（因无法本地复算，仅作合理性佐证，非提取依据）：
2023-03 全国累计 38,306,781（ZEIT ONLINE 引 RKI）；2024-04-08 全国累计 38,827,040（Statista 引 RKI）。
本表 39.20M，2024-04 → 2026-09 增量约 37.5 万，与地方性流行阶段的低速增长相符。

## 7. `bs.xlsx` —— 400 县基本信息表（sheet `Sheet1`）

**原始来源**：`原始数据/OD/Merging_List_Districts.csv`（401 行 × 6 列
`AGS num, AGS Text, Lat, Lon, Name, Type`）+ 由 `cn.xlsx` 派生的通勤统计量。

### 7.1 可从原始数据推导的 19 列

| 列 | 来源 | 处理 |
|---|---|---|
| `db_ID` | 规范行序 | `0..399` |
| `pos.x` | `Merging_List_Districts.csv` | `Lon`（注意经度在前） |
| `pos.y` | `Merging_List_Districts.csv` | `Lat` |
| `pos2.x` / `pos2.y` | 同上 | 与 `pos.x` / `pos.y` **完全相同**（非质心，无区分） |
| `local_commuter_type1` | `cn.xlsx` | 矩阵**对角线** `OD[i][i]`（本地通勤） |
| `out_commuter_type1` | `cn.xlsx` | 矩阵**行和** `Σ_j OD[i][j]`（从 i 出发） |
| `in_commuter_type1` | `cn.xlsx` | 矩阵**列和** `Σ_i OD[i][j]`（流入 j） |
| `commuter_type1` | `cn.xlsx` | 与 `out_commuter_type1` **完全相同** |
| `area` | 占位 | 恒为 `1` |
| `sub_percentage` | 占位 | 恒为 `1` |
| `sub_area km2` / `area_km2` | 占位 | 恒为 `1`（**无真实面积**，故 `pop_den` 实际等于人口） |
| `pop_den` | 派生 | 恒等于 `population` 列 |
| `pop_den (normal)` | 占位 | 恒为 `1` |
| `age 0-14` / `age 15-64` / `age 65+` | 占位 | 恒为 `0.15` / `0.65` / `0.2`（**全国统一值，非分县年龄结构**） |
| `railroad_zone` | 占位 | 恒为 `0` |

**坐标回连方式**：`bs.xlsx` 的县名与 `Merging_List_Districts.csv` 的 `Name + ", " + Type`
**不一致**（116/400 不同；例：`Kiel, Landeshauptstadt, Kreisfreie Stadt`（本表）vs `Kiel, Kreisfreie Stadt`
（`Name=Kiel` + `Type=Kreisfreie Stadt`）；`Lübeck, Hansestadt, Kreisfreie Stadt` vs `Lübeck, Kreisfreie Stadt`；
`Dithmarschen, Landkreis` vs `Dithmarschen, Kreis`；`Rhein-Kreis Neuss`（本表无类型后缀）vs `Rhein-Kreis Neuss, Kreis`），
因此**不能按名字连接**。实测可靠做法是**按经纬度连接**（5 位小数容差，400/400 唯一命中），
连接后再按 `AGS num` 排序即得规范行序。
（`bs.county` 内部无重名，400 个取值两两不同，故重名不是问题所在；差异全部来自命名约定。）

### 7.2 不可从原始数据推导的 3 列（外部来源）

| 列 | 状态 |
|---|---|
| `county` | 400 个规范标签，与 `Merging_List_Districts.csv` 的 `Name + ", " + Type` 写法不同（116/400）。全文检索确认：**337/400 个完整标签在本仓库原始数据中根本不出现**（仅 63 个恰好与 `Name` 字段逐字相同），说明该列的命名约定来自本仓库之外。例：`Kiel, Landeshauptstadt, Kreisfreie Stadt`（本表）vs `Kiel, Kreisfreie Stadt`；`Kreisfreie Stadt Rostock, Hansestadt` vs `Rostock, Kreisfreie Stadt` |
| `town` | 与 `county` **逐行完全相同**（400/400），并非独立的城镇名 |
| `population` | 与 `flu/population.csv` 的任何一年列都**不精确相等**（0/400 命中）。最接近 2018 年列：L1 = 569,902，平均相对偏差 0.96%，仅 76/400 落在 ±0.1% 内；对 2000→2019 两端做线性插值的全局最佳分数年份为 **t = 2018.09**（L1 = 528,841）。说明它是**另一个官方统计口径/发布版本**的人口数，不是 `population.csv` 的某一列 |

因此 `build_tables.py` 从现有 `bs.xlsx` 读取这 3 列作为**外部输入**，其余 19 列全部重新推导。
实测：重建的 22 列 × 400 行中，全部 8,000 个数值单元格与现有文件**逐一相等（L1 = 0）**，
`county`/`town` 文本列亦完全一致。

**结论**：`bs.xlsx` 中 `area` / `area_km2` / `sub_area km2` / `pop_den (normal)` /
`age 0-14..65+` / `railroad_zone` 共 9 列是**无实际含义的占位常数**，
EpiRank 计算中 `KEY_NORMALIZED_DENSITY`（`EpiRank_GUI.py:189-215`）= `log10(density + 1)`，
其中 `density` 直接取自 `bs.xlsx` 第 13 列 `pop_den`（**并不再除以 `area`**），
故因 `pop_den ≡ population`，它实际退化为**人口数的单调变换**。

## 10. 一句话汇总

- 全部 6 份表格共用**同一 400 县行序**：`Merging_List_Districts.csv` 去掉 AGS 16056(Eisenach) 后按 AGS 升序；
- `Flu` = `cases.csv` 前 400 行 × 末 312 周列求和（1,024,212 例）；
- `ev` = RKI 肠病毒周报全时段按县求和（172 例，实际只有 2015 年、仅萨克森州 11 县）；
- `nv` = RKI 诺如**年发病率** × `population.csv` 人口 ÷ 1e5，逐年求和后取整（635,413 例，2020 人口沿用 2019）；
- `cn` = 2024 年出行矩阵对 4 个维度求和得 400×400（14,311 条非零边，2.56 亿人次）；
- `bs` = `Merging_List_Districts.csv` 坐标 + `cn` 矩阵的行/列/对角线和 + 9 列占位常数，
  其中 `county`/`town`/`population` 三列为**外部来源，不在本仓库原始数据内**；
- `COVID-19` = RKI 2026-09-12 全量快照按 `NeuerFall∈{0,1}` 汇总（39,201,579 例），
  但本地原始 CSV 仅为 LFS 指针，`git lfs pull` 取回后即可由 `build_tables.py` 自动复现。
